## 2. CRDT 节点基座

### 2.1 节点属性

前端可定位节点增加：

```ts
type CrdtNodeIdentityAttributes = {
  nodeId: string
  nodeVersion: number
}
```

约定：

- `nodeId`：节点生命周期内稳定不变的 UUID；删除后不复用。
- `nodeVersion`：节点自身的数值版本，初始值为 `0`。
- 节点的 `type`、`attrs`、`content`、`marks` 发生持久化变化时递增 `nodeVersion`。
- 纯位置移动、重排或父节点变化不递增 `nodeVersion`。
- 新建节点时生成 `nodeId`，复制、粘贴或导入节点时生成新的 `nodeId`。
- 节点在文档内移动时保留原有 `nodeId`。

### 2.2 `resourceReference` 兼容

- `resourceReference` 的 `refId` 与通用 `nodeId` 使用相同值。
- 新建资源引用时同时生成 `nodeId` 和 `refId`。
- 复制资源引用时同时生成新的 `nodeId` 和 `refId`。
- 移动或修改已有资源引用时保留原有 `nodeId` 和 `refId`。
- 历史资源引用中的 `refId` 不替换；缺失 `nodeId` 时只补充 `nodeId`。

### 2.3 历史节点补齐

通过一次性、幂等的 Yjs 数据迁移补齐历史节点：

1. 读取文档当前快照和待合并更新，合并为最新状态。
2. 遍历 `content` 中的节点，仅补充缺失的 `nodeId` 和 `nodeVersion`。
3. 使用稳定的节点结构身份生成历史 `nodeId`，不能覆盖已有身份。
4. 写回补齐后的快照。
5. 前端启动时只校验属性完整性，不由多个客户端随机生成历史节点身份。

## 3. Elasticsearch `file` 索引

### 3.1 索引文档

每个可被 `[[ ]]` 引用的资源对应一条 ES 文档：

```text
_id = {resourceType}:{resourceId}
```

字段定义：

| 字段 | ES 类型 | 说明 |
| --- | --- | --- |
| `fileName` | `text` + `keyword` | NOTE 使用标题，IMAGE 使用文件名，DOCUMENT 使用文档标题。 |
| `resourceType` | `keyword` | `NOTE`、`IMAGE`、`DOCUMENT`。 |
| `resourceId` | `keyword` | 业务资源 ID，以字符串形式保存。 |
| `resourceUrl` | `keyword` | 仅 IMAGE 填充，来自 `biz_image.oss_url`，不参与搜索。 |
| `visibleUserIds` | `keyword[]` | 非公开资源的可见用户 ID。 |
| `isPublic` | `boolean` | 是否满足公开可见条件。 |
| `isDelete` | `boolean` | 删除标记，查询必须过滤为 `false`。 |

建议 Mapping：

```json
{
  "properties": {
    "fileName": {
      "type": "text",
      "fields": {
        "keyword": {
          "type": "keyword"
        }
      }
    },
    "resourceType": { "type": "keyword" },
    "resourceId": { "type": "keyword" },
    "resourceUrl": { "type": "keyword", "index": false },
    "visibleUserIds": { "type": "keyword" },
    "isPublic": { "type": "boolean" },
    "isDelete": { "type": "boolean" }
  }
}
```

NOTE 和 DOCUMENT 省略 `resourceUrl`，不写入空字符串。公开资源通过 `isPublic` 表达，不使用 `visibleUserIds = ["*"]`。

### 3.2 数据源映射

| 数据表 | `resourceType` | `fileName` | `resourceUrl` | 删除条件 | 可见范围 |
| --- | --- | --- | --- | --- | --- |
| `biz_note` | `NOTE` | `title` | 不填充 | `status = 8` | 所有者；`status = 6` 时公开。 |
| `biz_image` | `IMAGE` | `filename` | `oss_url` | `audit_status = 4` | 所有者；`is_public = 1 AND audit_status = 2` 时公开。 |
| `biz_document` | `DOCUMENT` | `title` | 不填充 | `deleted = 1` | 所有者和启用中的 `biz_document_user` 用户。 |

非公开资源将所有者和有效授权用户写入 `visibleUserIds`。查询条件为：

```text
isDelete = false
AND (isPublic = true OR visibleUserIds contains currentUserId)
```

写入约定：

- 资源创建、名称、公开状态、删除状态或 IMAGE URL 变化时，完整重建对应 ES 文档。
- `biz_document_user` 变化时，重新读取该文档全部有效授权用户。
- 软删除保留索引文档并设置 `isDelete = true`；硬删除可以删除 ES 文档。
- 所有写入使用稳定 `_id`，必须支持重复消费和重试。
- ES `file` 索引是 MySQL 的查询投影，MySQL 仍为事实源。

## 4. Canal 消费者与查询接口

### 4.1 Canal 监听表

| 表 | 关注字段 | 刷新资源 |
| --- | --- | --- |
| `biz_note` | `title`、`status`、`user_id` | `NOTE:{id}` |
| `biz_image` | `filename`、`user_id`、`is_public`、`audit_status`、`oss_url` | `IMAGE:{id}` |
| `biz_document` | `title`、`owner_user_id`、`deleted` | `DOCUMENT:{id}` |
| `biz_document_user` | `document_id`、`user_id`、`permission`、`enabled` | `DOCUMENT:{document_id}` |

### 4.2 消息链路

```text
MySQL Binlog
→ Canal Consumer
→ FileIndexRefreshEvent
→ RabbitMQ
→ ES Projection Consumer
→ 读取当前 MySQL 状态并重建 file 文档
```

Canal 事件只携带资源定位信息：

```json
{
  "eventId": "binlog-file-offset-row",
  "resourceType": "DOCUMENT",
  "resourceId": "789",
  "sourceTable": "biz_document_user",
  "sourcePosition": "mysql-bin.000001:12345"
}
```

处理约定：

- Canal 发布 RabbitMQ 成功后再确认 Canal 批次。
- ES 消费者重新读取 MySQL 当前状态，避免使用过期行数据覆盖最新状态。
- `DOCUMENT` 变化时重新计算完整 `visibleUserIds`。
- 失败消息通过 RabbitMQ 重试，最终进入死信队列。
- 首次上线提供全量重建任务，增量同步和全量重建都必须幂等。
- Canal 数据库名和表过滤规则必须与应用实际业务数据库一致。

### 4.3 `[[ ]]` 资源查询接口

```http
GET /user/file/completion?keyword={keyword}&limit={limit}
```

返回：

```json
[
  {
    "fileName": "Redis 使用笔记",
    "resourceType": "NOTE",
    "resourceId": "123"
  },
  {
    "fileName": "Redis 架构图.png",
    "resourceType": "IMAGE",
    "resourceId": "456",
    "resourceUrl": "https://example.com/redis.png"
  }
]
```

接口约定：

- `keyword` 用于名称前缀或关键词匹配。
- `limit` 默认 10，最大 20。
- 过滤 `isDelete = false`，并按当前用户过滤 `isPublic` 和 `visibleUserIds`。
- 不向前端返回 `visibleUserIds`。
- 只返回双链插入所需的候选信息，不承担综合搜索。
