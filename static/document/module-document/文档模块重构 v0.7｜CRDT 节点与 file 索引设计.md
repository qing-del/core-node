# 文档模块重构 v0.7｜CRDT 节点与 `file` 索引设计

> v0.7 提供 CRDT 节点基础属性、面向 `[[ ]]` 双链补全的资源索引，以及旧笔记、媒体资源、协同文档的增量同步。本版本不包含 Agent 节点操作和综合搜索。

## 1. 目标与边界

### 1.1 目标

- 为首发注册的 CRDT 文本节点增加 `nodeId`、`nodeVersion`。
- 通过一次性迁移补齐历史节点缺失的节点属性。
- 建立 Elasticsearch `file` 索引，用于 `[[ ]]` 资源候选搜索。
- 使用 Canal 监听资源变化，增量刷新 `file` 索引。
- 提供基于当前用户和 token scope 的双链补全查询接口。

### 1.2 边界

- 首发不注册 `doc` 根节点、`text` 文本叶子节点、`bulletList`、`orderedList` 和其他非纯文本节点。
- 不实现文档正文、Markdown 上下文、标签和综合全文搜索。
- 不改造 Yjs 服务端合并逻辑。
- 不监听正文、标签、Yjs 日志和旧关系投影表。
- Agent 节点投影和操作规范以 `core-agent` 项目为准：
  `/Users/m3air/Desktop/code/core-agent/static/document/collaborative/CORE-AGENT-Detail-01.md`
- 本文只提供 Agent 后续使用所需的节点身份和版本基座，不定义 Agent 能力或节点操作。

## 2. CRDT 节点基座

### 2.1 首发注册节点

首发注册以下纯文本节点：

```text
paragraph
heading
listItem
blockquote
codeBlock
```

`resourceReference` 不提供 Agent 操作能力，只提供身份基座。`doc`、`text`、列表容器和其他非纯文本节点暂不注册。

### 2.2 节点属性与生命周期

注册节点增加：

```ts
type CrdtNodeIdentityAttributes = {
  nodeId: string
  nodeVersion: number
}
```

- `nodeId` 是节点生命周期内稳定不变的 UUID；删除后不复用。
- `nodeVersion` 是节点自身的数值版本，新节点从 `0` 开始。
- 节点自身的文本、属性、格式或结构内容发生持久化变化时递增 `nodeVersion`。
- 子节点变化不递增祖先节点版本。
- 纯移动、重排和父节点变化不递增 `nodeVersion`。
- 新建节点生成新的 `nodeId`；复制、粘贴、导入时为复制树中的注册节点生成新的 `nodeId`。
- 节点在文档内移动时保留原有 `nodeId`。

### 2.3 `resourceReference` 兼容

- `resourceReference` 的 `refId` 与 `nodeId` 使用相同值。
- 新建、复制和导入资源引用时同时生成新的 `nodeId`、`refId`。
- 移动或修改已有资源引用时保留原有 `nodeId`、`refId`。
- 历史引用缺失 `nodeId` 时使用已有 `refId` 补齐。
- 已有 `nodeId` 与 `refId` 不一致时，迁移失败并记录，不静默覆盖。

### 2.4 历史节点补齐

通过独立的一次性迁移任务补齐历史节点：

1. 保证文档写入一致性，读取当前快照、持久化 Yjs 日志和 pending 更新。
2. 合并为最新状态并遍历已注册节点。
3. 只填充缺失的 `nodeId`、`nodeVersion`；已有值不得覆盖。
4. `resourceReference` 按 `nodeId = refId` 规则处理；身份不一致时记录迁移失败。
5. 生成新快照，并通过 `persisted_log_id` CAS 写回。
6. 迁移失败支持重试；重复执行不会重新生成或覆盖已有身份。
7. 完成后校验每个注册节点均具备 `nodeId` 和数值型 `nodeVersion`。

## 3. Elasticsearch `file` 索引

### 3.1 索引文档

每个可被 `[[ ]]` 引用的资源对应一条 ES 文档：

```text
_id = {resourceType}:{resourceId}
```

字段定义：

| 字段 | ES 类型 | 说明 |
| --- | --- | --- |
| `fileName` | `text` + `keyword` | NOTE 使用标题，IMAGE 使用文件名，DOCUMENT 使用文档标题。 |
| `resourceType` | `keyword` | `NOTE`、`IMAGE`、`DOCUMENT`。 |
| `resourceId` | `keyword` | 业务资源 ID，以字符串形式保存。 |
| `resourceUrl` | `keyword` | 仅 IMAGE 填充，来自 `biz_image.oss_url`，不参与搜索。 |
| `visibleUserIds` | `keyword` | 实际值为字符串数组，保存非公开资源的可见用户 ID。 |
| `isPublic` | `boolean` | 是否满足公开可见条件。 |
| `isDelete` | `boolean` | 删除标记。 |

NOTE 和 DOCUMENT 不写入 `resourceUrl`。公开资源通过 `isPublic` 表达，不使用 `visibleUserIds = ["*"]`。

- 参考 [Elasticsearch索引创建.md](static/dataCentre/Elasticsearch索引创建.md)

### 3.2 索引创建示例

使用项目已有的 Elasticsearch Java Client 8.17 创建索引和 Mapping。示例只负责初始化，不负责资源写入、全量重建或查询：

索引创建使用稳定索引名 `file`；已有索引直接跳过，Mapping 与本节字段定义保持一致。

### 3.3 数据源映射

| 数据表 | `resourceType` | `fileName` | `resourceUrl` | 删除条件 | 可见范围 |
| --- | --- | --- | --- | --- | --- |
| `biz_note` | `NOTE` | `title` | 不填充 | `status = 8` | 所有者；`status = 6` 时公开。 |
| `biz_image` | `IMAGE` | `filename` | `oss_url` | `audit_status = 4` | 所有者；`is_public = 1 AND audit_status = 2` 时公开。 |
| `biz_document` | `DOCUMENT` | `title` | 不填充 | `deleted = 1` | 所有者和启用中的 `biz_document_user` 用户。 |

写入约定：

- 资源创建、名称、公开状态、删除状态或 IMAGE URL 变化时，完整重建对应 ES 文档。
- `biz_document_user` 变化时，重新读取该文档全部有效授权用户。
- 软删除保留索引文档并设置 `isDelete = true`；硬删除时删除对应 ES 文档。
- 所有写入使用稳定 `_id`，支持重复消费和重试。
- ES `file` 索引是 MySQL 的查询投影，MySQL 仍为事实源。

## 4. Canal 消费者与查询接口

### 4.1 Canal 配置与监听表

Java Client 的连接配置以 `static/dataCentre/canal-java-client-config.md` 为准：

- MySQL 数据库：`personal_saas`
- Canal destination：`example`
- Canal TCP 端口：`11111`
- 服务端过滤：`personal_saas[.].*`

监听表：

| 表 | 关注字段 | 刷新资源 |
| --- | --- | --- |
| `biz_note` | `title`、`status`、`user_id` | `NOTE:{id}` |
| `biz_image` | `filename`、`user_id`、`is_public`、`audit_status`、`oss_url` | `IMAGE:{id}` |
| `biz_document` | `title`、`owner_user_id`、`deleted` | `DOCUMENT:{id}` |
| `biz_document_user` | `document_id`、`user_id`、`permission`、`enabled` | `DOCUMENT:{document_id}` |

### 4.2 消息链路

```text
MySQL Binlog
→ Canal Consumer
→ FileIndexRefreshEvent
→ RabbitMQ
→ ES Projection Consumer
→ 读取当前 MySQL 状态并重建 file 文档
```

Canal 事件只携带资源定位信息。Canal 发布 RabbitMQ 成功后确认批次；ES 消费者重新读取 MySQL 当前状态。失败消息使用现有 RabbitMQ 重试和死信队列，首次上线提供幂等的全量重建任务。

不监听正文、标签、Yjs 日志和旧关系投影表。

### 4.3 `[[ ]]` 资源查询接口

```http
GET /user/file/completion?keyword={keyword}&limit={limit}
```

查询规则：

```text
prefix fileName.keyword = keyword
AND isDelete = false
AND (isPublic = true OR visibleUserIds contains currentUserId)
```

请求必须携带 token；`currentUserId` 和 scope 从 token 解析，不接受前端传入用户 ID。

资源类型与 scope 的对应关系：

| 资源类型 | 所需 scope |
| --- | --- |
| `NOTE` | `note:read` |
| `IMAGE` | `media:read` |
| `DOCUMENT` | `document:read` |

按当前项目的 scope 匹配规则判断权限。缺少某类资源的 read scope 时，在 ES 查询中追加对应的 `must_not resourceType` 条件；例如缺少 `media:read` 时排除 `IMAGE`。

接口约定：

- `limit` 默认 10，最大 20。
- 过滤已删除资源和当前用户不可见资源。
- 不向前端返回 `visibleUserIds`。
- `resourceUrl` 仅在 IMAGE 返回。
- 只返回双链插入所需的候选信息，不承担正文、标签和综合搜索。

返回示例：

```json
[
  {
    "fileName": "Redis 使用笔记",
    "resourceType": "NOTE",
    "resourceId": "123"
  },
  {
    "fileName": "Redis 架构图.png",
    "resourceType": "IMAGE",
    "resourceId": "456",
    "resourceUrl": "https://example.com/redis.png"
  }
]
```

## 5. v0.7 完成标准

### 5.1 实施顺序

1. 为注册节点和 `resourceReference` 增加属性，并完成复制、粘贴、导入处理。
2. 增加历史节点一次性补齐任务和快照 CAS 写回。
3. 创建 `file` Mapping、索引初始化和全量重建任务。
4. 增加 Canal Client、刷新事件、RabbitMQ 消费者和 ES 投影重建。
5. 增加带 token scope 过滤的 `GET /user/file/completion` 接口。
6. 将 `[[ ]]` 候选查询切换到 `file` 索引。

### 5.2 验收标准

- `paragraph`、`heading`、`listItem`、`blockquote`、`codeBlock` 具备稳定的 `nodeId` 和数值型 `nodeVersion`。
- `resourceReference` 的 `nodeId` 与 `refId` 一致；复制生成新身份，移动保留原身份。
- 历史节点补齐任务幂等，已有身份不被覆盖，身份冲突可被发现。
- `file` 索引覆盖 NOTE、IMAGE、DOCUMENT。
- IMAGE 的 `resourceUrl` 来自 `biz_image.oss_url`，其他资源不填充。
- 名称、公开状态、权限、删除状态和 IMAGE URL 变化可以同步到 ES。
- 缺少对应 read scope 的资源类型不会出现在 ES 查询结果中。
- `[[ ]]` 只返回当前用户可见且未删除的资源。
- middleware 文档不定义 Agent 的能力注册、读取、写入、范围编辑或冲突处理。
