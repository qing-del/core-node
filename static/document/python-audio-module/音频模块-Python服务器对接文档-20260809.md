## 1. 本版结论

Python 服务必须实现两类消费者：

1. 消费生成任务，先回调开始、再执行 TTS/FFmpeg、最后回调成功或失败；
2. 消费资源删除消息，安全且幂等地删除最终音频文件。

当前实现的关键约束如下：

- Java 通过 `AUDIO_QUEUE_TYPE` 在 Redis Stream 和 RabbitMQ 中二选一，Python 只消费实际启用的一种；
- 生成消息包含 `attempt`，开始与完成回调必须原样回传；
- 两个回调都必须携带 `X-Callback-Token`；
- 统一业务成功码为 `code=1`，但是否接受本轮处理取决于 `data`；
- 成功完成必须提交非空 `resultUrl` 和大于 `0` 的文件字节数 `AudioSize`；
- Java 拒绝本轮结果时，Python 不得保留该轮产生的孤儿文件；
- 删除消息可能重复、可能没有 `resultUrl`，删除消费者必须幂等。

### 2.2 Java 配置

| 配置 | 作用 | 当前默认值 |
| --- | --- | --- |
| `AUDIO_QUEUE_TYPE` | 生成与删除消息使用的队列实现 | `redis-stream` |
| `jacolp.audio.callback-token` | Python 回调认证 Token | 无安全默认值，部署时必须提供 |

可选队列值：

- `redis-stream`：启用 Redis 生成任务与删除消息发布器；
- `rabbitmq`：启用 RabbitMQ 生成任务与删除消息发布器，并声明持久化 Exchange/Queue/Binding。

同一个 Java 实例只会启用一种发布实现。Python 不要同时消费两套队列，否则会造成重复处理或消费无效消息。

## 3. 生成任务消息

所有消息字段均按字符串读取，再由 Python 做严格转换与校验。

```json
{
  "taskId": "10086",
  "attempt": "0",
  "userId": "999",
  "speed": "1.5",
  "noiseType": "WHITE_NOISE",
  "noiseFactor": "0.3",
  "text": "需要生成的文本"
}
```

| 字段 | Python 建议类型 | 约束 |
| --- | --- | --- |
| `taskId` | `int` | Java 任务 ID |
| `attempt` | `int` | 非负；回调时原样传回，不得自行递增 |
| `userId` | `int` | 任务所属用户 |
| `speed` | `Decimal` | `0.50 ~ 3.00` |
| `noiseType` | `str` | `PURE`、`WHITE_NOISE`、`PINK_NOISE`、`BROWN_NOISE`、`CAFE`、`AIRPORT`、`SUBWAY` |
| `noiseFactor` | `Decimal` | `0.00 ~ 2.00` |
| `text` | `str` | 非空待生成文本 |

### 3.1 Redis Stream

- Stream：`stream:audio:tasks`
- Consumer Group：`audio-consumer-group`
- 消息格式：Redis Stream Hash 字段

### 3.2 RabbitMQ

- Exchange：`audio.generate.exchange`
- Routing Key：`audio.generate`
- Queue：`audio.generate.queue`
- 消息格式：持久化 UTF-8 JSON

Java 当前只声明持久化直连交换机、队列和绑定，没有声明音频专用 DLX。Python 若需要延迟重试或死信队列，应在部署拓扑中明确配置，不能假设 Java 已创建。

## 4. 回调通用协议

基础路径：`/common/audio`

请求头：`X-Callback-Token: <与 Java 配置一致的 token>`

连通性检查：

```http
GET /common/audio/callback/test
X-Callback-Token: <token>
```

开始和完成回调的正常 HTTP 响应均使用统一结构：

```json
{
  "code": 1,
  "msg": "success",
  "data": true
}
```

处理响应时必须依次判断 HTTP 状态、`code` 和 `data`：

- HTTP `401`：Token 错误，停止无界重试并报警；
- 网络错误或 HTTP `5xx`：结果未知，保留处理上下文并有限退避重试；
- `code=0`：参数或业务校验失败，记录 `msg`，不要把它当作成功；
- `code=1, data=true`：本次状态变更被 Java 接受；
- `code=1, data=false`：任务状态或 `attempt` 不再接受本轮状态变更。

## 5. 开始处理回调

```http
POST /common/audio/callback/start
Content-Type: application/json
X-Callback-Token: <token>
```

```json
{
  "taskId": 10086,
  "attempt": 0
}
```

- `data=true`：Java 已用 `taskId + PENDING + attempt` 做 CAS，将任务更新为 `PROCESSING`；Python 可以开始生成。
- `data=false`：可能是重复消息、旧轮次、任务已取消/删除或已进入终态；Python 不生成文件，并 ACK 当前消息。
- 请求结果未知：不要开始生成；保留消息并有限重试开始回调。同一次处理始终使用消息中的 `attempt`。

## 6. 完成回调

### 6.1 成功

必须先完成文件写入并关闭文件句柄，再读取真实大小：

```python
audio_size = os.path.getsize(output_path)
```

```http
POST /common/audio/callback/finish
Content-Type: application/json
X-Callback-Token: <token>
```

```json
{
  "taskId": 10086,
  "attempt": 0,
  "status": 2,
  "resultUrl": "/audio/10086.mp3",
  "AudioSize": 5242880
}
```

| 字段 | JSON 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `taskId` | integer | 是 | 生成消息中的任务 ID |
| `attempt` | integer | 是 | 生成消息中的非负轮次 |
| `status` | integer | 是 | 成功固定为 `2` |
| `resultUrl` | string | 是 | 非空最终访问地址 |
| `AudioSize` | integer（Java `Long`） | 是 | 最终文件真实字节数，必须大于 `0` |

Java 兼容接收 `audioSize` 别名，但 Python 应统一发送规范字段名 `AudioSize`。

Java 的成功处理顺序为：

1. 校验状态、URL、大小和本轮 `attempt`；
2. 占用用户存储配额；
3. 以 `taskId + PROCESSING + attempt` 做 CAS，写入 `SUCCESS`、URL、大小和完成日期；
4. 若 CAS 失败，回滚刚占用的存储配额。

响应处理：

- `code=1, data=true`：保留最终文件并 ACK 生成消息；
- `code=1, data=false` 且本次 HTTP 请求结果明确：Java 未接受本轮结果，幂等删除本轮文件并 ACK；
- 网络中断、超时或 HTTP `5xx`：结果可能已经提交成功，不要立刻删除文件，也不要构造新 `attempt`；有限重试同一完成回调并报警。

已知边界：当前完成接口对“成功结果已写入但响应丢失”的重放不会返回幂等 `true`。因此，首次请求结果未知后若重试得到 `data=false`，不能仅凭这次响应判断文件是否从未被接受；需要保留稳定的 `resultUrl`，记录任务 ID/轮次并交由运维核对，避免删除 Java 已登记的文件。

### 6.2 失败

```json
{
  "taskId": 10086,
  "attempt": 0,
  "status": -1,
  "errorMsg": "ffmpeg conversion failed"
}
```

失败回调不需要 `resultUrl` 或 `AudioSize`，只允许相同轮次从 `PROCESSING` 更新为 `FAILED`。`data=false` 表示当前任务或轮次已不再接受失败结果。

## 7. 超时重试与轮次隔离

Java 每 5 分钟扫描一次超过 10 分钟未更新的 `PENDING`/`PROCESSING` 任务：

- 当 `retry_time < 3` 时，将任务重置为 `PENDING`、`retry_time + 1`，再发布新消息；
- 当 `retry_time >= 3` 且任务再次超时时，将任务标记为 `FAILED`；
- 因此自动处理轮次可能是 `attempt=0、1、2、3`，Python 不得自行生成下一轮次。

开始和完成回调都会比较 `attempt`。旧消费者即使在新轮次发布后才完成，也只能得到 `data=false`，不能覆盖新轮次结果或重复占用配额。

## 8. 资源删除消息

任务被用户或管理员删除并且数据库事务提交后，Java 发布删除消息。

Payload：

```json
{
  "taskId": "10086",
  "userId": "999",
  "resultUrl": "/audio/10086.mp3",
  "audioSize": "5242880"
}
```

Redis 模式：

- Stream：`stream:audio:deletions`
- Consumer Group：`audio-delete-consumer-group`

RabbitMQ 模式：

- Exchange：`audio.delete.exchange`
- Routing Key：`audio.delete`
- Queue：`audio.delete.queue`

删除消费者要求：

- `resultUrl` 为空时直接 ACK；
- 文件不存在时视为成功并 ACK；
- 从可信音频根目录解析 URL，规范化路径后再次确认目标仍在根目录内；
- 禁止把消息中的 URL 直接拼成任意文件系统路径；
- 临时 IO 错误采用有限重试，超过阈值后报警或进入部署时配置的死信流程；
- Java 已在删除任务时释放存储配额，Python 不需要回调配额变更。

## 9. 推荐处理骨架

```python
def handle_generate(message):
    task_id = int(message["taskId"])
    attempt = int(message["attempt"])

    started = callback_start(task_id=task_id, attempt=attempt)
    if started.is_rejected:
        ack(message)
        return
    if not started.is_confirmed:
        retry_later_without_ack(message)
        return

    output_path = None
    try:
        output_path, result_url = generate_to_final_file(message)
        response = callback_finish(
            taskId=task_id,
            attempt=attempt,
            status=2,
            resultUrl=result_url,
            AudioSize=os.path.getsize(output_path),
        )
        if response.is_accepted:
            ack(message)
        elif response.is_definitively_rejected:
            safe_remove(output_path)
            ack(message)
        else:
            retain_file_and_retry_same_callback(message, output_path)
    except Exception as exc:
        callback_finish(
            taskId=task_id,
            attempt=attempt,
            status=-1,
            errorMsg=str(exc)[:500],
        )
        if output_path:
            safe_remove(output_path)
        retry_or_ack_by_consumer_policy(message, exc)


def handle_delete(message):
    result_url = message.get("resultUrl", "")
    if result_url:
        safe_remove(resolve_and_verify_under_audio_root(result_url))
    ack(message)
```

## 10. 联调验收清单

- 新任务消息包含 `attempt=0`，开始与完成回调原样回传；
- 旧轮次回调在超时重投后得到 `data=false`，不覆盖新轮次；
- 成功回调保存 URL、真实字节数并扣减存储配额；
- 剩余配额刚好等于 `AudioSize` 时成功；配额不足时任务转为 `FAILED`，Python 删除孤儿文件；
- 排队中取消后，开始回调返回 `data=false`；
- 处理中取消或删除后，明确的完成回调返回 `data=false`，Python 清理本轮文件；
- 删除消息重复投递、文件不存在和空 `resultUrl` 均可安全 ACK；
- Token 错误返回 HTTP `401`，消费者报警且不无限重试；
- 模拟完成回调响应丢失，确认消费者不会直接删除可能已登记的文件；
- 对实际部署使用的 Redis Stream 或 RabbitMQ 完成一次生成、失败、超时重试和删除端到端验证。
