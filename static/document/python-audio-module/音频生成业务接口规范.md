# 音频生成业务与接口规范

文档版本：2.0.0

更新时间：2026-08-09

Python 服务的部署与消费者实现以[音频模块 Python 服务器对接文档（2026-08-09）](音频模块-Python服务器对接文档-20260809.md)为准。

## 1. 架构与职责

音频生成链路为：

```text
Java API -> MySQL audio_tasks -> Redis Stream 或 RabbitMQ -> Python 音频工作进程 -> Nginx/对象存储
```

Java 负责用户鉴权、任务持久化、配额、状态机和消息发布。Python 只消费当前部署启用的队列，执行 TTS/FFmpeg，并通过受保护的回调接口报告结果。

队列由 `AUDIO_QUEUE_TYPE` 选择：

- `redis-stream`：默认值；
- `rabbitmq`：使用持久化 Exchange、Queue 和消息。

同一 Java 实例只启用一种生成队列实现，Python 不应同时消费两种模式。

## 2. 生成参数

### 2.1 背景音类型

| `noiseType` | 含义 | Python/FFmpeg 参考 |
| --- | --- | --- |
| `PURE` | 纯净人声 | 不混入背景音 |
| `WHITE_NOISE` | 白噪音 | `anoisesrc=c=white:r=44100` |
| `PINK_NOISE` | 粉色噪音 | `anoisesrc=c=pink:r=44100` |
| `BROWN_NOISE` | 褐噪音 | `anoisesrc=c=brown:r=44100` |
| `CAFE` | 咖啡厅 | `anoisesrc=c=pink:r=44100,lowpass=f=2000` |
| `AIRPORT` | 飞机场 | `anoisesrc=c=brown:r=44100,lowpass=f=500,tremolo=f=0.5:d=0.3` |
| `SUBWAY` | 地铁车厢 | `anoisesrc=c=brown:r=44100,lowpass=f=300,tremolo=f=4.0:d=0.8` |

### 2.2 数值范围

| 参数 | 类型 | 范围 | 默认值/说明 |
| --- | --- | --- | --- |
| `speed` | Decimal | `0.50 ~ 3.00` | 必填；Python 转换为 TTS 语速参数 |
| `noiseFactor` | Decimal | `0.00 ~ 2.00` | 可选，Java 默认 `0.50` |

## 3. 数据与状态

### 3.1 `audio_tasks` 关键字段

| 字段 | 说明 |
| --- | --- |
| `id` | 任务 ID |
| `user_id` | 提交用户 |
| `source_text` | 原始文本 |
| `speed` / `noise_type` / `noise_factor` | 生成参数 |
| `status` | 当前任务状态 |
| `retry_time` | 当前处理轮次；队列和回调中名为 `attempt` |
| `result_url` | 成功后的访问地址 |
| `audio_size` | 成功文件的真实字节数 |
| `error_msg` | 失败原因 |
| `completed_date` | 成功日期，用于清理 |

状态值：

| 值 | 状态 | 说明 |
| ---: | --- | --- |
| `0` | `PENDING` | 等待处理 |
| `1` | `PROCESSING` | 当前轮次正在处理 |
| `2` | `SUCCESS` | 已成功 |
| `-1` | `FAILED` | 已失败 |
| `-2` | `RETRIED` | 原失败任务已由用户创建新任务重试 |
| `-3` | `CANCELLED` | 已取消 |

### 3.2 处理轮次 `attempt`

新任务的 `attempt` 为 `0`。Java 发现任务处理超时后，会先原子地将任务重置为 `PENDING` 并递增 `attempt`，再发布新消息。

Python 必须把队列消息中的 `attempt` 原样回传。Java 的开始和完成回调均比较 `taskId + status + attempt`；旧轮次回调返回 `data=false`，不能覆盖新轮次结果。

## 4. 生成队列契约

所有生成消息字段均按字符串读取，包括 `attempt`。

```json
{
  "taskId": "10086",
  "attempt": "0",
  "userId": "999",
  "speed": "1.5",
  "noiseType": "WHITE_NOISE",
  "noiseFactor": "0.3",
  "text": "需要生成的文本"
}
```

### 4.1 Redis Stream

- Stream：`stream:audio:tasks`
- Consumer Group：`audio-consumer-group`
- 消息：Hash 字段

### 4.2 RabbitMQ

- Exchange：`audio.generate.exchange`
- Routing Key：`audio.generate`
- Queue：`audio.generate.queue`
- 消息：持久化 JSON，字段与上方一致

## 5. 用户 API

所有 HTTP 示例中的业务成功码均为 `code=1`；`code=0` 表示参数或业务失败。

### 5.1 提交生成任务

```http
POST /user/audio/generate
Content-Type: application/json
```

```json
{
  "text": "需要生成的文本",
  "speed": 1.5,
  "noiseType": "WHITE_NOISE",
  "noiseFactor": 0.3
}
```

成功响应：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "taskId": 10086,
    "status": 0
  }
}
```

### 5.2 查询任务状态

```http
GET /user/audio/status/{taskId}
```

成功响应示例：

```json
{
  "code": 1,
  "msg": "success",
  "data": {
    "id": 10086,
    "status": 2,
    "resultUrl": "/audio/10086.mp3",
    "audioSize": 5242880,
    "errorMsg": null
  }
}
```

## 6. Python 回调协议

两个回调都必须包含：

```http
Content-Type: application/json
X-Callback-Token: <双方约定的 token>
```

Token 必须与 Java 配置 `jacolp.audio.callback-token` 一致。Token 错误返回 HTTP `401`，工作进程应报警并停止无界重试。

统一成功响应：

```json
{
  "code": 1,
  "msg": "success",
  "data": true
}
```

除检查 HTTP 状态和 `code` 外，Python 必须检查 `data`。`data=false` 表示 Java 拒绝了本次状态变更。

### 6.1 开始处理

```http
POST /common/audio/callback/start
```

```json
{
  "taskId": 10086,
  "attempt": 0
}
```

- `data=true`：本轮任务已从 `PENDING` 原子更新为 `PROCESSING`，可以开始生成；
- `data=false`：任务已取消、删除、重复消费、进入终态或消息轮次已过期。不要生成，直接按队列策略 ACK。

### 6.2 成功完成

```http
POST /common/audio/callback/finish
```

```json
{
  "taskId": 10086,
  "attempt": 0,
  "status": 2,
  "resultUrl": "/audio/10086.mp3",
  "AudioSize": 5242880
}
```

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `taskId` | 是 | 队列中的任务 ID |
| `attempt` | 是 | 队列中的非负处理轮次 |
| `status` | 是 | 成功固定为 `2` |
| `resultUrl` | 是 | 非空的最终访问地址 |
| `AudioSize` | 是 | 文件关闭后读取的真实字节数，必须大于 `0`；Java 也兼容别名 `audioSize` |

响应处理：

- `code=1, data=true`：Java 已保存结果和占用存储配额，保留文件并 ACK；
- `code=1, data=false`：任务状态或轮次不再接受该结果，删除本次文件并 ACK；
- `code=0`：请求校验失败，记录 `msg`，不要保留未被 Java 接受的文件；
- 网络或 Java 临时故障：按有限退避策略重试同一完成回调，不能构造新的 `attempt`。

### 6.3 失败完成

```json
{
  "taskId": 10086,
  "attempt": 0,
  "status": -1,
  "errorMsg": "ffmpeg conversion failed"
}
```

失败回调不需要 `resultUrl` 或 `AudioSize`，只允许相同轮次从 `PROCESSING` 更新为 `FAILED`。

## 7. 资源删除队列

用户或管理员删除任务后，Java 在事务提交后发布幂等资源删除消息。

Redis 模式：

- Stream：`stream:audio:deletions`
- Consumer Group：`audio-delete-consumer-group`

RabbitMQ 模式：

- Exchange：`audio.delete.exchange`
- Routing Key：`audio.delete`
- Queue：`audio.delete.queue`

Payload：

```json
{
  "taskId": "10086",
  "userId": "999",
  "resultUrl": "/audio/10086.mp3",
  "audioSize": "5242880"
}
```

删除消费者必须校验解析后的路径仍位于可信音频根目录。文件不存在也视为成功；`resultUrl` 为空时直接 ACK。

## 8. Python 处理流程

1. 从当前启用的队列读取 `taskId`、`attempt` 和生成参数。
2. 调用开始回调并原样传递 `attempt`；只有 `code=1, data=true` 才继续。
3. 执行 TTS 和 FFmpeg，写入临时文件后原子移动到最终位置。
4. 文件关闭后读取实际大小，调用完成回调并原样传递 `attempt`。
5. Java 拒绝结果时幂等删除本轮输出文件。
6. 按 Redis Stream 或 RabbitMQ 的策略 ACK；临时基础设施错误采用有限重试和告警，不能无限循环。

## 9. 联调验收

- 新任务消息包含 `attempt=0`，开始与完成回调均回传 `0`；
- 超时重投消息的 `attempt` 递增，旧轮次开始/完成回调返回 `data=false`；
- 成功回调保存 URL、真实文件大小并扣减存储配额；
- 配额不足、取消或删除时，完成回调返回 `data=false`，Python 删除本轮文件；
- Token 错误返回 HTTP `401`；
- 实际部署选择的 Redis Stream 或 RabbitMQ 模式完成一次生成和删除端到端测试。
