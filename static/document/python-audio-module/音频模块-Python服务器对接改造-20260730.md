## 1. 本次必须完成的 Python 改动

1. 生成消息新增 `attempt`；开始和完成回调必须原样回传，用于隔离超时重试轮次。
2. 成功回调必须携带 `AudioSize`，值为最终音频文件的实际字节数。
3. 严格处理开始回调和完成回调的 `data`：只要为 `false`，就停止后续处理或删除本次生成的文件。
4. 新增音频资源删除消息消费者，支持幂等删除文件。
5. 继续携带 `X-Callback-Token` 请求头调用 Java 回调。

部署 Java 服务前先执行数据库迁移：

迁移脚本必须按 `static/database/migrations` 文件名顺序执行。与本协议直接相关的脚本为：

- `20260726_audio_task_retry_time.sql`：新增非空 `retry_time`；
- `20260730_refactor_mq.sql`：兼容新增 `audio_size` 并补充 `CANCELLED(-3)` 状态说明。

## 2. 生成任务消费流程

生成任务消息增加 `attempt` 字段。所有消息字段均按字符串读取。

### 2.1 Redis Stream 模式

- Stream：`stream:audio:tasks`
- Consumer Group：`audio-consumer-group`
- 字段均为字符串：

```json
{
  "taskId": "10086",
  "attempt": "0",
  "userId": "999",
  "speed": "1.5",
  "noiseType": "WHITE_NOISE",
  "noiseFactor": "0.3",
  "text": "需要生成的文本"
}
```

### 2.2 RabbitMQ 模式

- Exchange：`audio.generate.exchange`
- Routing Key：`audio.generate`
- Queue：`audio.generate.queue`
- 消息：持久化 JSON，字段与上方相同。

Java 通过环境变量 `AUDIO_QUEUE_TYPE` 选择队列实现：`redis-stream`（默认）或 `rabbitmq`。Python 只消费部署环境实际启用的实现。

## 3. 回调协议

基础路径：`/common/audio`  
认证请求头：`X-Callback-Token: <双方约定的 token>`

统一响应结构：

```json
{
  "code": 1,
  "msg": "success",
  "data": true
}
```

`code=1` 表示接口正常处理；Python 还必须继续判断 `data`。

### 3.1 开始处理回调

```http
POST /common/audio/callback/start
Content-Type: application/json
X-Callback-Token: <token>
```

```json
{
  "taskId": 10086,
  "attempt": 0
}
```

处理规则：

- `data=true`：任务已从 `PENDING` 原子更新为 `PROCESSING`，可以开始生成。
- `data=false`：任务已被取消、删除、重复消费、状态不再允许处理，或消息轮次已过期。Python 不得生成音频，应确认/ACK 当前消息。

### 3.2 成功回调（本次有变更）

```http
POST /common/audio/callback/finish
Content-Type: application/json
X-Callback-Token: <token>
```

```json
{
  "taskId": 10086,
  "attempt": 0,
  "status": 2,
  "resultUrl": "/audio/10086.mp3",
  "AudioSize": 5242880
}
```

字段约束：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `taskId` | Integer | 是 | 音频任务 ID |
| `attempt` | Integer | 是 | 队列消息中的非负处理轮次，必须原样回传 |
| `status` | Integer | 是 | 成功固定为 `2` |
| `resultUrl` | String | 是 | 非空的最终访问 URL |
| `AudioSize` | Long（JSON integer） | 是 | 最终文件实际大小，单位为 byte，必须大于 0；字段名大小写按此文档发送 |

建议在文件完全写入并关闭后读取大小：

```python
audio_size = os.path.getsize(output_path)
```

Java 的处理顺序为：

1. 校验 `resultUrl` 与 `AudioSize`。
2. 原子占用该用户的存储配额。
3. 使用包含 `attempt` 的 CAS 将任务从 `PROCESSING` 更新为 `SUCCESS`，并保存 URL、大小和完成日期。
4. 若第 3 步因并发取消/删除失败，立即回滚第 2 步占用的存储。

响应处理：

- `code=1, data=true`：保存成功，Python 可保留文件并 ACK 消息。
- `code=1, data=false`：Python 必须删除刚生成的文件并 ACK 消息。常见原因：
  - 用户剩余存储不足；Java 已将任务标记为 `FAILED`，失败原因为 `存储空间不足`。
  - 生成过程中用户或管理员取消/删除了任务。
  - 回调重复到达，任务已是终态。
  - 当前消息的 `attempt` 已被超时重试产生的新轮次替代。
- `code=0`：请求参数或业务校验失败。Python 不得保留未被 Java 接受的文件；记录 `msg` 后按重试策略处理，确认不会再重试时删除文件并 ACK。
- HTTP `401`：回调 Token 错误，应停止消费并报警，不要无限重试。

### 3.3 失败回调

生成或转码失败时不需要 `AudioSize`：

```json
{
  "taskId": 10086,
  "attempt": 0,
  "status": -1,
  "errorMsg": "ffmpeg conversion failed"
}
```

失败回调仅允许任务从 `PROCESSING` 更新为 `FAILED`。`data=false` 表示任务已经取消、删除或进入其他终态。

## 4. 新增资源删除消息

用户或管理员删除音频任务后，Java 会在数据库事务提交成功后发送资源删除消息。Python 必须新增独立消费者。

### 4.1 Redis Stream 模式

- Stream：`stream:audio:deletions`
- Consumer Group：`audio-delete-consumer-group`
- Payload：

```json
{
  "taskId": "10086",
  "userId": "999",
  "resultUrl": "/audio/10086.mp3",
  "audioSize": "5242880"
}
```

### 4.2 RabbitMQ 模式

- Exchange：`audio.delete.exchange`
- Routing Key：`audio.delete`
- Queue：`audio.delete.queue`
- 消息：持久化 JSON，字段与上方相同。

### 4.3 删除消费者要求

- 删除操作必须幂等：文件不存在也视为成功。
- `resultUrl` 可能为空，例如用户删除了尚未生成完成的任务；此时直接 ACK。
- 不要根据客户端传入路径直接拼接任意文件系统路径。应从可信的音频根目录解析 URL，并校验最终路径仍位于该根目录内。
- 删除成功或文件本来不存在：ACK。
- 临时 IO 错误：按队列策略有限重试；超过阈值进入死信或告警，不要无限循环。
- `audioSize` 是审计辅助字段；Java 在逻辑删除成功时已经释放用户配额，Python 不需要回调存储变更。

## 5. 取消与并发场景

任务新增状态 `-3=CANCELLED`。取消只允许发生在 `PENDING` 或 `PROCESSING`。

- 排队阶段取消：Python 后续消费到生成消息时，开始回调返回 `data=false`，应直接 ACK。
- 生成阶段取消：Python 可能无法中断正在执行的 TTS/FFmpeg；完成回调将返回 `data=false`，应删除输出文件并 ACK。
- 删除任务：开始或完成回调同样返回 `data=false`；同时 Python 还可能收到独立的资源删除消息。两个删除路径都必须幂等。

## 6. 推荐 Python 伪代码

```python
def handle_generate(message):
    task_id = int(message["taskId"])
    attempt = int(message["attempt"])
    start_response = callback_start({"taskId": task_id, "attempt": attempt})
    if start_response.get("code") != 1 or start_response.get("data") is not True:
        ack(message)
        return

    output_path = None
    try:
        output_path, result_url = generate_audio(message)
        audio_size = os.path.getsize(output_path)
        response = callback_finish({
            "taskId": task_id,
            "attempt": attempt,
            "status": 2,
            "resultUrl": result_url,
            "AudioSize": audio_size,
        })
        if response.get("code") != 1 or response.get("data") is not True:
            safe_remove(output_path)
        ack(message)
    except Exception as exc:
        callback_finish({
            "taskId": task_id,
            "attempt": attempt,
            "status": -1,
            "errorMsg": str(exc)[:500],
        })
        if output_path:
            safe_remove(output_path)
        ack_or_retry_by_policy(message, exc)


def handle_delete(message):
    result_url = message.get("resultUrl", "")
    if result_url:
        safe_remove(resolve_under_audio_root(result_url))
    ack(message)
```

## 7. 联调验收清单

- 成功生成：`AudioSize` 正确，回调 `data=true`，任务保存 URL 与大小。
- 超时重试：新消息的 `attempt` 递增；旧消息的开始或完成回调均返回 `data=false`，且不扣减存储配额。
- 临界配额：剩余空间等于 `AudioSize` 时成功。
- 配额不足：回调 `data=false`，任务为 `FAILED`，原因为 `存储空间不足`，Python 文件被删除。
- 排队中取消：开始回调 `data=false`，Python 不生成。
- 处理中取消：完成回调 `data=false`，Python 删除刚生成文件。
- 成功任务删除：删除消息到达，Python 删除资源；重复投递仍成功。
- 未完成任务删除：`resultUrl` 为空，删除消费者正常 ACK。
- Token 错误：收到 HTTP 401，消费者报警并停止无限重试。
- Redis Stream 和 RabbitMQ 至少对实际部署使用的模式完成一次端到端验证。
